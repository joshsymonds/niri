# Integration manifest

This file documents what `josh/integration` currently includes. It's a
human-maintained snapshot that lives on integration only (not on patch
branches or main).

When you add, update, or remove a patch on `josh/integration` per the
"Maintaining integration" recipe in `CLAUDE.md`, **update this file in
the same change** so the next reader (human or agent) can tell at a
glance what's deployed without spelunking the merge graph.

| `josh/ffm-edge-deadzone` | local | Not yet PRed upstream | Adds an `edge-deadzone` property (logical pixels) to `focus-follows-mouse`. When set, FFM is suppressed if the cursor is within N pixels of any edge of the candidate window or on its niri border — the cursor must commit into the window's interior. Orthogonal to `max-scroll-amount`. Also changes the FFM same-check to compare against the layout's keyboard-focused window rather than the cursor's previous geometric window, so the deadzone re-evaluates on every motion until the cursor commits past it. |
| `josh/block-pointer-constraints` | local | [PR #4045](https://github.com/niri-wm/niri/pull/4045) open upstream | Adds a `block-pointer-constraints` window-rule (`Option<bool>`) that suppresses activation of `zwp_pointer_constraints_v1` for matching windows. Both `Locked` and `Confined` variants are suppressed unconditionally — the rule is opt-in per window. Gate is placed inside the `with_pointer_constraint` callback so the no-constraint fast path (every pointer motion over a surface without a constraint) is unchanged. Motivated by Zoom's `annotate_toolbar` overlay locking the cursor when crossed; specific apps that legitimately need pointer-lock (games, drawing tablets) are unaffected unless explicitly matched. |
| `josh/render-above-fullscreen` | local | Pushed to `origin`; upstream PR not yet filed | Adds a `render-above-fullscreen` window-rule (`Option<bool>`) that promotes a floating tile's render order from below-scrolling (current default, gets hidden behind fullscreen windows) to above-scrolling (renders on top of fullscreen). Implementation: new `FloatingRenderPass` enum, two-pass call to `Workspace::render_floating` in `Monitor::render_workspaces` with `AboveFullscreen` emitted first (smithay paints front-to-back, so first-emitted = topmost). The `AboveFullscreen` pass bypasses the `is_floating_visible()` early-return so flagged tiles render even when fullscreen is focused; `Workspace::window_under` parallel-handles the flagged subset for hit-test parity. Motivated by Zoom's `as_toolbar` and `zoom_linux_float_video_window` helpers losing visibility when the user fullscreens an unrelated app; generalizable to any always-on-top utility window (PiP video, annotation overlays). |
| `josh/floating-position-center` | local | Pushed to `origin`; upstream PR not yet filed | Adds `Center` to the `RelativeTo` enum on `default-floating-position`'s `relative-to` property. Centers a floating tile on both axes within the working area when `relative-to="center"` (matching the natural reading; previously you had to write `relative-to="top"` and then offset y to fake a center). One-commit precursor patch; the `josh/relative-to-window-config` branch carries the same `Center` work as part of a larger feature, so this branch's primary role is to provide the standalone PR shape if it ever upstreams. |
| `josh/relative-to-window-config` | local | Pushed to `origin`; upstream PR not yet filed | Adds `in-window-of` child block on `default-floating-position` that anchors a floating window inside another window's tile rectangle (resolved at dialog-map time via a layered Match filter: same-workspace → same-output → MRU). Maintains a reverse-indexed `AnchorIndex<TileId>` on `Layout` so dependents follow the target's geometry/workspace/output changes via a per-frame sweep in `advance_animations`. User-drag of the dependent breaks the anchor; target close orphans dependents (no re-resolve — MRU-at-open-time). Motivated by Zoom's "Leave meeting panel" floating dialog opening at working-area center where it straddles tile boundaries; the rule lets users anchor it inside the Meeting tile via `in-window-of title="^Meeting$"`. |
| `josh/block-focus-cursor-warp` | local | Pushed to `origin`; upstream PR not yet filed | Adds a `block-focus-cursor-warp` window-rule (`Option<bool>`) that suppresses niri's cursor-follows-focus warp for matching windows. Gate placed inside `State::move_cursor_to_focused_tile` after the existing early-returns: if the active window's resolved rule has `block_focus_cursor_warp == Some(true)`, the function short-circuits before computing the destination rect. Single chokepoint covers both `maybe_warp_cursor_to_focus` and `maybe_warp_cursor_to_focus_centered` (and any future warp wrapper). Motivated by Zoom's `annotate_toolbar` overlay (a 112×112 floating xdg_toplevel during screen-share-with-annotation) repeatedly calling `xdg_activation_v1.activate()` ~30Hz, which routed through the cursor-follows-focus warp and snapped the cursor to the toolbar's (56, 56) center every time the user moved the mouse. Opt-in per window, so apps that legitimately benefit from cursor warp on activation (notifications, freshly-launched apps) are unaffected unless explicitly matched. |
| `josh/scrolling-working-area-crop` | local | Pushed to `origin`; upstream PR not yet filed | Clips the scrolling-layer render to `Monitor.working_area` in normal mode so columns that scroll past the working-area edge are clipped at layer-shell exclusive zones (e.g. a left-anchored bar) instead of bleeding under them. Render-layer only — adds a private `compute_scrolling_crop_bounds` helper in `src/layout/monitor.rs` and a sibling `push_scrolling!` macro alongside the existing `push!` in `Monitor::render_workspaces`; only the `ws.render_scrolling(...)` call uses the new bounds. Floating / insert-hint / focus-flash keep the existing infinite crop (floating already clamps to working_area at the layout level). During `workspace_switch` / `overview_progress` the scrolling crop falls back to the existing HACK-guarded bounds so pixel-shader and GTK damage-tracking behavior is unchanged. Fullscreen is not special-cased — well-behaved layer-shell bars release `exclusive_zone = -1` on fullscreen, expanding the working area and making the crop a no-op. Motivated by a transparent DMS bar zone on DP-2 revealing that adjacent columns slid under the bar's reserved region when focus moved off the leftmost column. |
| `josh/ffm-suppress-during-view-animation` | local | Local-only; not for upstream | Suppresses `Niri::handle_focus_follows_mouse` while the active workspace's `ViewOffset` is animating on the output under the cursor. Sibling to the existing workspace-switch animation gate inside `Layout::should_trigger_focus_follows_mouse_on` — extends the same "FFM against a mid-animation moving target races the animation and cancels a deliberate keyboard commit" reasoning to view-offset (column-scroll) animations. Output-scoped via `new_focus.output` so an animation on output B never gates FFM on output A. Implementation: new `Layout::is_view_offset_animating_on(&Output) -> bool` predicate that delegates through `Monitor::active_workspace_ref → Workspace::view_offset_is_animation_ongoing → ScrollingSpace::view_offset_is_animation_ongoing → ViewOffset::is_animation_ongoing` (the canonical scroll-position-in-motion predicate at `scrolling.rs:3842`). One early-return added after the `window_mru_ui` bail and before `contents_under()`. No new state, no timestamps, no config knob — FFM's event-driven shape (only runs on PointerMotion events) supplies the "require new motion after animation ends" behavior automatically. Motivated by sub-pixel mouse jitter (resting hand, breathing) cancelling deliberate focus-window-{left,right} commands during the ~200-300ms spring animation. |
| `josh/screencast-polish` | local | Pushed to `origin`; upstream PR not yet filed | Multi-subsystem polish of niri's PipeWire screencast UX, motivated by Zoom on the desktop. Six subsystems shipped as one branch: (1) **`ActiveCasts` tracker** — `Screencasting::active_casts: ActiveCasts` is a derived `{outputs: HashSet<String>, windows: HashSet<u64>}` snapshot of which targets are being cast, recomputed via `recompute_active_casts` after every mutation of `Screencasting::casts` (start, dynamic target switch, pending-cast promotion, stop). Single source of truth read by every other subsystem here. (2) **`screen-cast` config section** in `niri-config` (`screen-cast { indicator { width, color }, hide-overlay-layer, hide-top-layer, hide-bottom-layer, hide-background-layer, hide-zoom-non-shared-windows }`). Defaults hide Top + Overlay layers, keep Bottom + Background, auto-hide Zoom non-shared windows. Indicator off by default (`width 0`). (3) **Indicator border decoration** — thin border drawn around the cast target on the local screen ONLY (gated on `RenderTarget::Output` at every call site so it cannot appear in cast frames by construction — the entire safety property). Output-cast indicator is a new `output_indicator_elements` helper in `render_helpers/screencast_indicator.rs` pushed from `Niri::render_inner` right after the layer-shell Overlay layer. Window-cast indicator is inline in `Tile::render_inner` after the focus-ring push, reusing `is_window_cast_target` via a new `LayoutElement` trait method. Indicator color defaults to a CSS-red `(1.0, 85/255, 85/255, 1.0)` constant hoisted to `niri-config` so both render sites share it. (4) **Layer-shell overlay hiding** — `Niri::render_layer_normal` / `render_layer_popups` short-circuit when `ctx.target ∈ {Screencast, ScreenCapture}` and the corresponding `hide-*-layer` flag is true. Layered ON TOP of (not in place of) per-surface `block_out_from` window/layer rules. Helper `screencast_hides_layer(sc: &ScreenCast, target, layer) -> bool` factored out for unit-test coverage. (5) **Zoom auto-hide** — new `Mapped::block_out_for_screencast_auto: bool` flag set by `Niri::refresh_screencast_auto_hide` (runs each `State::refresh`): true for niri-tracked windows whose Wayland app-id matches `zoom`/`Zoom` AND that are NOT themselves the cast target AND any cast is active AND the config flag is on. `Mapped::should_block_out(target)` (and the extracted pure helper `compute_should_block_out`) ORs this flag into the existing `RenderTarget::should_block_out(block_out_from)` check — the user-configured `block_out_from` rule is unchanged and continues to apply on top. The three render-side `should_block_out` call sites in `window/mapped.rs` and the MRU-thumbnail call site in `ui/mru.rs` all route through the new method. (6) **Window-sharing bug fix (Zoom blank-frame symptom)** — the DBus `org.gnome.Mutter.ScreenCast.Stream.parameters` property previously returned `(0, 0), (1, 1)` for window streams. Zoom evidently uses `parameters` as its display-surface size hint (before PipeWire negotiation), and a 1×1 hint produced the user-visible "shared window appears blank" bug. Fixed by threading a shared `WindowCastSizes` (`Arc<Mutex<HashMap<u64, (i32, i32)>>>`) map from `Screencasting` through `ScreenCast::new` / `Session::new` / `Stream::new`. `Niri::refresh_window_cast_sizes` runs each `State::refresh` and populates the map from `cast_params_for_window` (physical pixels — matches the PipeWire stream's negotiated buffer unit). `Stream::parameters` reads its window-id from the map, with a 1920×1080 fallback for windows that haven't rendered yet. PipeWire's stream-param update path continues to drive the real buffer geometry, so any size drift between refreshes is reconciled by the existing renegotiation. Branch carries 8 commits + 1 review-feedback commit. Indicator-leak invariant verified at every `RenderTarget::Output` call site. No new `is_screencast: bool` threaded through render code — `RenderTarget` enum remains the sole discriminator. Motivated by Zoom's window-share producing blank frames on niri (root cause: `parameters` 1×1 stub) plus the related UX wins of (a) knowing what's being cast and (b) keeping notifications + Zoom's own toolbar/gallery out of the cast stream. |
| `josh/screencast-lock-gate` | local | Local-only; not for upstream | Audit fix #2 (security). Per-window PipeWire screencasts (`CastTarget::Window`) leaked live window content while the session was locked — output-level casts and wlr-screencopy are gated inside `render_inner`, but the two window-content emission paths (`Niri::render_windows_for_screen_cast`, `State::redraw_cast`) render the window directly and bypassed that. Both now blank the buffer via `dequeue_buffer_and_clear` while `is_locked()`, so the stream stays alive and resumes on unlock (mirrors locked output-cast behavior). |
| `josh/mutter-x11-interop-filter` | local | Local-only; not for upstream | Audit fix #4 (security hardening). `MutterX11InteropManagerState` was the only privileged Wayland global registered with a `\|_\| true` filter; restricted (security-context-sandboxed) clients could bind it. Gated on `client_is_unrestricted` like every sibling global. Handler is currently a no-op, so no behavior change for legitimate clients — removes a latent escalation footgun and makes the privileged-global filter set uniform. |

## Tooling commit

Single commit at the base of integration (after `main`) carries
everything that should NOT bleed into upstream PRs:

- `justfile` — fork-maintenance recipes (`build`, `sync-upstream`, `rebase-patch`)
- `.envrc` — direnv glue to load the flake's nightly Rust + native deps
- `CLAUDE.md` — agent guide explaining the branch model + re-derivation
- `INTEGRATION.md` — this file
- `.gitignore` — adds `/worktrees`, `/reference` (out-of-tree dirs for git
  worktrees and the prior-art reference checkouts)

## reference/

The (gitignored) `reference/` directory holds shallow clones of other
projects whose code we use as reference when implementing or validating
patches. It's not part of any commit. Current contents:

- `mutter/` — GNOME's Wayland compositor; canonical xdg-desktop-portal-gnome
  producer. See `src/backends/meta-screen-cast-stream-src.c` for the
  reference DMA-BUF + SHM screencast implementation
  ([MR !1939](https://gitlab.gnome.org/GNOME/mutter/-/merge_requests/1939)).
- `kwin/` — KDE's Wayland compositor. See
  `src/plugins/screencast/screencaststream.cpp` for the C++-flavored
  reference, especially `buildFormats()` for the multi-pod pattern
  ([MR !1210](https://invent.kde.org/plasma/kwin/-/merge_requests/1210)).
- `kpipewire/` — KDE's PipeWire helper library. Consumer-side mirror of
  the same pod-construction pattern; useful for cross-checking version
  gates (`kDmaBufModifierMinVersion = {0, 3, 33}`).
- `xdg-desktop-portal-wlr/` — wlroots-family screencast portal. Pure C
  reference for the two-pod offering pattern in `src/screencast/pipewire_screencast.c`.
- `xdg-desktop-portal-hyprland/` — Hyprland's portal fork. Cleanest
  example of explicit `force_shm` and DMA-failure renegotiate logic
  in `src/portals/Screencopy.cpp`.
- `niri-pr-1791/*.patch` — the 19-commit `git format-patch` series of
  PR #1791, preserved as flat patch files for archaeology.

## Coordinating across worktrees and machines

`josh/integration` is long-lived and maintained, not regenerated.
Conflict resolutions live as durable merge commits on the branch.
If you're working in a `worktrees/<topic>/` subdir or on a parallel
machine, always `git pull --ff-only origin josh/integration` before
merging anything new in — never reset/force a regenerated tree over
it. That silently drops resolutions (2026-05 rerere-stale incident).

`nix-config`'s `niri-flake` input always points at `josh/integration`.
Testing a patch means testing it stacked with every other deployed
patch — never repoint the input at a single patch branch.

## Maintaining integration

See "Maintaining integration" in `CLAUDE.md` for the canonical recipe.

When patches are added, updated, or removed:
1. Merge / re-merge / `git revert -m 1` the relevant branch into `josh/integration`.
2. Update this file's table in the same change.
3. Run `just integration-check` (oracle gate) and `just build`.
4. `git push origin josh/integration` (plain push; `-f` only for history surgery).
